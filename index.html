1. 출력 규칙 강제·JSON 스키마 검증을 통한 LLM 자유 서술 응답의 모순 문제 해결

문제 상황

  • RAG에 사용되는 FAQ 중 중복·개선이 필요한 항목을 LLM이 검토하고, 그 결과를 관리자에게 보여주는 기능
  • LLM이 자유롭게 서술한 응답을 그대로 사용해, 같은 응답 안에서 판단과 권고가 어긋남 (예: 판단은 "중복 아님"인데 권고는 "병합")
  • 테스트셋 30건에서 판단과 근거가 모순되는 경우가 2건 발생

해결 과정

  • 대안 1: 프롬프트로 판단 기준·조치 규칙·응답 양식을 지정하고 일관성 지시 추가
    • 판단·근거·조치·요약에 같은 결론을 AI가 각각 서술해, 어긋날 수 있는 지점이 늘어나 판단·근거 모순이 오히려 2건 → 5건으로 늘어 제외
    • 결론이 "수정 불필요·추가 확인 필요"인 응답에서 상세 설명(판단 근거 자유 서술)을 작성하지 않는 형식 오류가 7건 추가 발견
      • "요약은 한 문장으로" 지시와 "상세 양식을 모두 채우라"는 요구가 충돌해, 조치할 내용이 없는 경우 한 줄 결론으로 끝낸 것으로 추정
  • 대안 2(채택): 출력 형식 자체를 JSON 스키마로 고정하고 서버가 형식을 검증
    • LLM은 판단 결과와 근거 문장만 작성하고, 조치 권고 문구는 서버가 판단 결과에 맞춰 조립
    • AI가 쓰던 긴 상세 설명을 없애, 같은 30건에서 응답 형식 오류 7건 → 0건으로 개선
    • 판단 값 누락·근거 누락은 서버가 거부해 오류로 반환(안전망)

결과

  • 같은 모델·같은 입력 30건으로 단계별 비교(FAQ 30건, Qwen3-4B 양자화 모델 사용, temperature 0 기준)
    • 모순: 최초 2건 → 프롬프트 개선 5건 → 출력 형식 고정 0건
    • 형식 오류: 최초 0건 → 프롬프트 개선 7건(상세 설명 누락) → 출력 형식 고정 0건
  • 프롬프트 지시만으로는 일관성을 보장하지 못했고, AI가 작성하는 항목을 줄이고 그에 맞춰 서버가 조립하는 구조로 바꾸어 어긋날 지점을 줄임

2. JSON 컬럼에 대량 데이터를 저장하다 발생한 MySQL Out of sort memory를 테이블 분리로 해결

문제 상황

  • 정합성 위반 건의 상세 메타데이터를 JSON 컬럼 한 칸에 모두 저장해, 위반 건수가 늘면 행 크기도 함께 커지는 구조
  • 위반이 2,472건 이상이면 행 크기가 sort_buffer_size(256KB)를 넘어, 해당 컬럼을 포함한 ORDER BY 조회에서
    Out of sort memory(ERROR 1038)가 발생

해결 과정

  • 대안 1: sort_buffer_size를 늘린다.
    • 임계값만 올라가고 건수가 늘면 같은 문제가 발생하여 제외
  • 대안 2: 위반 데이터를 담을 수 있는 건수를 제한해서 컬럼에 담는다.
    • 상한을 넘는 위반 데이터의 상세정보가 유실되어 제외
  • 대안 3(채택): 위반을 별도 테이블로 분리
    • 기존 테이블에는 위반 건수만 저장, 별도의 violation 테이블을 만들어 위반 1건당 1레코드로 메타데이터를 저장
    • 모든 위반을 보존하면서 행 크기를 건수와 무관하게 고정

결과

  • 수정 전: 위반 2,472건부터 Out of sort memory(ERROR 1038) 발생
  • 수정 후: 같은 조건에서 위반 40만 건까지 정렬·조회 모두 정상 작동
